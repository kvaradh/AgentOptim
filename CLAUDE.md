structure, using RDKit + PyTDC + scikit-learn.

## Issues encountered

- **`nbconvert` JSON validation error** when converting a cell's type from code to markdown via `NotebookEdit`: the tool left stale `execution_count`/`outputs` fields on the markdown cell, which `nbconvert --execute` rejected as invalid notebook JSON (it still ran, but printed a validation error). Fixed by stripping `execution_count`/`outputs` from all markdown cells via a one-off script. Watch for this again any time a cell's type is changed rather than freshly inserted.
- **`numpy` 2.x breaks RDKit's `ConvertToNumpyArray`** in this project's RDKit build (2023.09.6, predates numpy 2.0's release): `conda install xgboost` pulled numpy up to 2.2.6 as a dependency, and the very next `featurize()` call failed with `ValueError: Expecting a Numeric array object` inside `compute_morgan_fp`. Fixed with `conda install -n admet -c conda-forge "numpy<2"` (resolved to 1.26.4), which restored both RDKit and xgboost working together. If a future package install pulls numpy back to 2.x, watch for this again — either re-pin numpy, or check whether the installed RDKit version has since been upgraded past this incompatibility.
- **`XGBClassifier` + scikit-learn 1.7.2's `'roc_auc'` string scorer silently returns NaN**, not an error — the same `xgboost` install pulled scikit-learn up to 1.7.2, and its newer classifier auto-detection doesn't recognize this XGBoost version's classifier in that specific scorer code path (`.predict_proba()` called directly still works fine, so plain model use is unaffected — only scikit-learn's internal string-scorer dispatch, e.g. inside `cross_val_score`/`RandomizedSearchCV` with `scoring='roc_auc'`, hits it). Confirmed via `error_score='raise'`: `ValueError: XGBClassifier should either be a classifier... Got a regressor with response_method=predict_proba instead.` Fix: use an explicit callable scorer (`def proba_roc_auc(estimator, X, y): return roc_auc_score(y, estimator.predict_proba(X)[:, 1])`) instead of the `'roc_auc'` string, anywhere `XGBClassifier` goes through scikit-learn's CV/search scoring machinery. `RandomForestClassifier` is unaffected.
